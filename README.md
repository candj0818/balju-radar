# 발주 레이더

월 판매량과 재고로 공장별 발주일과 발주 수량을 계산하는 웹 도구입니다.

## 쓰는 주소 (로그인 필요 없음)

**https://candj0818.github.io/balju-radar/**

- 휴대폰·PC 어디서나 이 주소를 열면 됩니다. 직원도 GitHub 계정이 필요 없습니다.
- 처음 여는 기기에서만 **접속 키**를 한 번 넣습니다. 키 만드는 법은 첫 화면의 안내를 따르세요.
- 데이터(판매량·재고·공장·발주 기록)는 이 저장소가 아니라 **비공개 저장소 `balju-radar-data`** 에 저장됩니다. 이 공개 저장소에는 프로그램만 있습니다.

## 파일

- `balju-radar.html` — 프로그램 원본 (claude.ai 페이지에도 같은 파일을 씀)
- `index.html` — GitHub Pages용. `python build.py`로 원본에서 자동 생성
- `build.py` — index.html 생성 스크립트

## 계산 요약

- **예상 판매**: 최근 6개월 가중평균. 중간값의 2배 초과·절반 미만인 달은 경계값으로 보정. 12개월 이상이면 계절성 반영(1년치 50%, 2년치 75%).
- **오늘 재고**: 재고 입력일부터 오늘까지 예상 판매분을 빼서 추정. 7일 넘게 갱신하지 않으면 경고.
- **안전재고**: 확률 계수(95% = 1.65) × 월 판매량 표준편차 × √(리드타임 ÷ 30)
- **발주점**: 리드타임 동안 판매량 + 안전재고
- **공장별 묶음 발주**: 공장에서 가장 급한 제품 날짜에, 다음 발주 주기 전에 필요한 제품을 함께 발주
- **수량 규칙**: MOQ 이상, 주문 배수(기본 5)와 박스 입수를 모두 만족하도록 올림
- **40HC 컨테이너**: 공장마다 따로 적재(기본 64CBM, 26,000kg). 박스 CBM은 가로·세로·높이로 계산하거나 직접 입력. 빈 공간은 입고 시점 재고일수가 낮은 제품부터 채워 공장 전체가 고르게 같은 일수를 갖도록(최대 120일치). 마지막 컨테이너가 30% 미만이면 급하지 않은 품목을 다음 발주로 미룸.

## 저장 방식

- 저장할 때마다 최신 데이터를 받아 내가 바꾼 항목만 덮어 합친 뒤 올립니다. 두 사람이 동시에 저장해도 서로의 변경이 지워지지 않습니다.
- 인터넷이 끊기면 변경 내용을 기기에 보관했다가 연결되면 자동으로 올립니다.
- 모든 저장은 `balju-radar-data` 저장소의 커밋 기록으로 남아, 예전 상태로 되돌릴 수 있습니다.
